# 경제 다큐 스튜디오 (Economic Docu Studio)

경제 주제 하나만 넣으면 AI가 **최신 뉴스 리서치 → 대본(후킹→현황→원인→과거사례→영향→
숫자→전문가관점→전망→정리) → 장면별 실제 시각자료(뉴스 사진/차트/그래프/로고/지도) →
내레이션 → 자막 → 렌더링**까지 전부 자동으로 처리해 사용자가 고른 길이(5~110분)의 경제·
시사 뉴스 롱폼 영상을 만들어 주는 프로그램입니다.

이 프로젝트는 원래 조선시대 야담(전래 이야기)을 AI 삽화로 만드는 프로그램이었습니다.
이번 전환은 겉모습만 바꾼 것이 아니라 파이프라인의 성격 자체를 바꾼 것입니다 — 야담은
"허구를 그럴듯하게 지어내는" 도구였지만, 이 프로그램은 **실제 뉴스에 근거해 사실을
정확하게 전달**하는 것을 최우선으로 합니다:

- 장면의 화면은 AI가 지어낸 삽화가 아니라 **실제 사진/차트/그래프/로고/지도**를 우선
  사용합니다(불가능한 추상적 개념 설명 장면에서만 AI 보조 그래픽으로 대체).
- 대본의 모든 챕터는 **리서치 단계에서 실제로 검색·확인한 사실**에만 근거해서 쓰이고,
  어떤 뉴스(언론사·URL)에서 나온 사실인지 화면과 데이터에 함께 남습니다.
- 목표 길이는 5·10·20·30·60·90·110분 중 고르거나 자유 입력할 수 있고, 그 값이 대본
  분량·장면 수·렌더링 길이 전체에 그대로 반영됩니다(특정 길이로 고정되어 있지 않음).

기획 기준은 유튜브 경제 롱폼 채널 65곳·6,975편을 전수 분석한 실측 자료("떡상채널 미니북
② — 경제 채널 시장 실측", 2026-08-03)입니다. 아래 수치는 전부 그 실측 결과에서 그대로
가져온 것입니다.

- **길수록 조회수가 오릅니다** — 60분+ 영상이 10~20분 대비 중앙 조회수 9.3배. 다만 60분+
  중 71%는 이미 나온 편들을 묶은 "통합본"이고, 새로 하나를 만들 때는 **개별 편 20~40분
  이상**이 실전 권장값입니다.
- **이기는 서사는 "붕괴·몰락"** — 상위 100편의 37%가 나라·기업·부동산·화폐가 "무너진다"는
  프레임(그 외 대비 ×1.22). 담백한 "쉬운 경제 설명"형은 오히려 감점 요소가 섞여 있습니다.
- **제목 문법**: 따옴표 포함 ×1.4, 숫자 포함 ×1.11. "됐다"(×5.88) "무너진"(×2.88) 같은
  단언형 키워드는 가점, 물음표(×0.77)·대괄호(×0.31)는 감점.
- **게시 시각은 오후 14시**가 최적(중앙 조회수 최고 시간대의 9.3배), 저녁 17~19시는 경쟁이
  치열해 불리.
- **채널 규모는 클수록 유리**(10만+ 구독 채널이 1만 미만 대비 조회수 중앙값 30.3배) —
  야담(사연) 시장과 정반대로, 브랜드/신뢰가 누적되는 시장입니다.

## 핵심 흐름

```
로그인(Google/네이버) → 내 프로젝트(새로 시작 / 이어서 작업하기)
  → 경제 주제 입력 → 최신 뉴스 리서치(사실관계+출처 확보) → 대본 생성(훅/챕터/정리)
  → 장면 분할 + "무엇을 보여줄지" 판단 → 실제 시각자료 소싱(사진/차트/로고/그래프)
  → 전체 내레이션(TTS) → 편집(전체 검토/수정) → 검수(렌더링 준비 확인)
  → 렌더링(ffmpeg) → 완성된 mp4
```

로그인한 사용자별로 프로젝트가 분리되어 저장됩니다(`lib/auth.ts`,
`lib/economic/authGuard.ts`). 각 단계는 프로젝트 파일
(`data/economic-projects/<id>/project.json`)에 자동으로 체크포인트 저장됩니다 — 사용자가
따로 "저장" 버튼을 누를 필요가 없습니다.

- 장면 시각자료·내레이션은 **장면 하나 단위로 상태(대기/생성 중/완료/오류)를 저장**하므로,
  실패한 장면만 골라 재시도할 수 있고 이미 완료된 것은 다시 만들지 않습니다.
- 로그인 후 뜨는 **"내 프로젝트"** 화면에서 진행 중이던 프로젝트를 이름으로 구분해 열 수
  있고, 이름 변경·삭제도 그 자리에서 바로 할 수 있습니다.
- 오류가 나면 어느 단계·몇 번째 항목에서 무슨 오류였는지 `project.errorLog`에 영구
  기록되어, "검수" 탭에서 서버를 껐다 켜도 이전 오류 이력을 확인할 수 있습니다.

## 1. 설치

```bash
npm install
```

`ffmpeg`는 별도 설치가 필요 없습니다(설치 시 플랫폼에 맞는 실행 파일이 자동으로 함께 받아짐).

## 2. 환경 변수

```bash
cp .env.local.example .env.local
```

| 키 | 용도 | 필수 여부 |
|---|---|---|
| `OLLAMA_HOST` / `OLLAMA_MODEL` | 대본·장면판단 생성(로컬 LLM, 아래 2-1번 참고) | 필수(설치 필요) |
| `PIPER_BIN` / `PIPER_VOICE_MODEL` | 내레이션 음성 합성 — Piper로 바꾸고 싶을 때만(아래 2-2번 참고). Windows는 기본적으로 내장 음성을 자동으로 써서 불필요 | 선택(Windows는 불필요) |
| `NEXTAUTH_SECRET` / `NEXTAUTH_URL` | 로그인 세션 서명 키 / 서비스 주소 | 필수 |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | Google 로그인 (아래 3번 참고) | 둘 중 하나 |
| `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET` | 네이버 로그인 (아래 3번 참고) | 둘 중 하나 |
| `GOOGLE_CSE_API_KEY` / `GOOGLE_CSE_CX` | 실제 사진/로고/지도 이미지 검색 보강(선택, 기본은 위키미디어) | 선택 |
| `CAPTION_FONT_PATH` | 자막용 한글 폰트 경로 직접 지정(선택) | 선택 |

뉴스 리서치(구글 뉴스 RSS)와 실제 이미지 검색(위키미디어 공용)은 키가 필요 없어 표에 없습니다.
Google/네이버 중 최소 한 쌍을 설정하지 않으면 로그인 자체가 불가능해 프로그램을 쓸 수 없고,
Ollama가 설치·실행되어 있지 않으면 대본 생성 단계에서, 내레이션 음성이 준비 안 됐으면(Windows
한국어 음성 미설치 또는 Piper 미설정) 내레이션 단계에서 설치 방법을 안내하는 오류가 뜹니다.

### 2-1. 로컬 LLM 설정 (Ollama) — 대본/장면판단 생성

완전 무료, 신용카드 등록 불필요, 하루 요청 한도 없음(사용자 PC에서 직접 실행되므로).

1. https://ollama.com 에서 OS에 맞는 설치 파일 받아 설치
2. 터미널에서 모델 받기: `ollama pull qwen2.5:7b-instruct` (한국어 지시 이행 능력이 준수한
   7B급 모델을 기본값으로 씁니다 — PC 사양이 넉넉하면 더 큰 모델로 바꿔도 되고, `.env.local`의
   `OLLAMA_MODEL`만 바꾸면 됩니다)
3. 설치하면 보통 자동으로 백그라운드에서 실행됩니다(수동 실행: `ollama serve`)
4. 기본 포트(11434)를 쓰면 `.env.local`에 아무것도 안 넣어도 되고, 바꿨다면 `OLLAMA_HOST`
   지정

**품질 참고**: 로컬 LLM은 Gemini보다 한국어 롱폼 대본 작성 품질이 떨어질 수 있습니다(특히
복잡한 JSON 형식 지시를 안 지키는 경우가 더 잦습니다) — 결과가 부자연스러우면 더 큰 모델로
바꿔보세요.

### 2-2. 내레이션 음성 합성(TTS) 설정

**Windows를 쓴다면 별도 설치가 필요 없습니다.** Windows 자체에 내장된 음성 합성 기능(SAPI)을
자동으로 씁니다 — 아래만 확인하세요.

1. Windows 설정(⊞+I) > 시간 및 언어 > 음성 > "음성 추가" > **한국어** 검색 후 설치
   (이미 한국어 음성이 있다면 이 단계는 건너뛰어도 됩니다)
2. 설치 후 프로그램(서버)을 재시작하면 자동으로 그 음성을 씁니다. `.env.local`에 아무것도
   추가하지 않아도 됩니다.

**Windows가 아니거나(macOS/Linux) 다른 음성을 쓰고 싶다면** Piper(오픈소스 로컬 TTS)를 쓸 수
있습니다 — 다만 Piper 공식 저장소는 한국어를 정식 지원하지 않고 커뮤니티가 변환한 모델만
있어서(안정성 미검증), Windows 사용자에게는 권장하지 않습니다.
1. https://github.com/rhasspy/piper 릴리스 페이지에서 OS에 맞는 실행 파일 내려받기
2. 한국어 음성 모델(.onnx 파일 + 짝을 이루는 .onnx.json 파일) 구해서 내려받기
3. `.env.local`에 `PIPER_BIN`(실행 파일 경로)과 `PIPER_VOICE_MODEL`(.onnx 파일 경로) 지정
   — 이 값을 넣으면 Windows 내장 음성 대신 Piper가 쓰입니다.
4. .onnx.json의 `"sample_rate"` 값이 22050이 아니면 `PIPER_SAMPLE_RATE`도 그 값으로 지정

Gemini TTS의 화자 프리셋(Charon/Kore 등) 같은 다중 선택은 없습니다 — 설치/설정된 음성
하나로 고정됩니다.

## 3. 로그인 설정 (Google / 네이버)

이 프로그램은 로그인해야 쓸 수 있습니다(작업물이 사용자별로 분리 저장되므로). 로그인은
[NextAuth](https://next-auth.js.org)로 구현했고, DB 없이 쿠키 기반 세션만 씁니다.

**Google**
1. https://console.cloud.google.com/apis/credentials 접속 → 프로젝트 선택(또는 생성)
2. "OAuth 동의 화면" 설정(외부/테스트 사용자로 시작해도 됨)
3. "사용자 인증 정보 만들기" → "OAuth 클라이언트 ID" → 애플리케이션 유형 "웹 애플리케이션"
4. 승인된 리디렉션 URI에 `{NEXTAUTH_URL}/api/auth/callback/google` 추가
   (로컬 개발이면 `http://localhost:3000/api/auth/callback/google`)
5. 발급된 클라이언트 ID/보안 비밀번호를 `.env.local`의 `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`에 입력

**네이버**
1. https://developers.naver.com/apps 접속 → "애플리케이션 등록"
2. 사용 API에 "네이버 로그인" 추가
3. 서비스 URL과 콜백 URL에 각각 `{NEXTAUTH_URL}`, `{NEXTAUTH_URL}/api/auth/callback/naver` 입력
4. 발급된 Client ID/Secret을 `.env.local`의 `NAVER_CLIENT_ID`/`NAVER_CLIENT_SECRET`에 입력

**세션 시크릿**: `NEXTAUTH_SECRET`은 아무 값이나 되지만, 터미널에서 `openssl rand -base64 32`로
만든 무작위 값을 넣는 걸 권장합니다.

Google/네이버 중 하나만 설정해도 됩니다.

## 4. 실행

```bash
npm run dev
```

브라우저에서 http://localhost:3000 접속 → 로그인 → "내 프로젝트" 화면에서 새 프로젝트를
시작하거나 기존 프로젝트를 이어서 엽니다.

## 5. 무료로 되는 부분 / 유료가 필요한 부분

이 프로젝트는 원래 Gemini API(무료 등급)로 리서치/대본/이미지/음성을 전부 처리했지만,
**무료 등급의 하루 요청 횟수 한도가 롱폼 영상 하나를 완성하기엔 너무 낮다는 문제**(실사용
결과 완성까지 한 달 가까이 걸림)가 있어서, 전부 무료·무제한 로컬/공개 API 조합으로
바꿨습니다. 지금은 **API 키가 하나도 필요 없고(로그인용 Google/네이버 OAuth 제외), 하루
요청 한도도 없습니다.**

| 기능 | 방식 | 무료 여부 |
|---|---|---|
| 뉴스 리서치(최신 동향/배경/영향 검색) | 구글 뉴스 RSS(키 불필요) | 완전 무료, 한도 없음 |
| 리서치 결과 요약/종합 | 로컬 LLM(Ollama, 사용자 PC에서 실행) | 완전 무료, 한도 없음 |
| 대본 생성 | 로컬 LLM(Ollama) | 완전 무료, 한도 없음 |
| 장면 분할 + "무엇을 보여줄지" 판단 | 로컬 LLM(Ollama) | 완전 무료, 한도 없음 |
| 실제 수치 기반 데이터 카드(주가/통계 그래프) | ffmpeg로 직접 렌더링 | 완전 무료 |
| 실제 사진/로고/지도 이미지 검색 | 위키미디어 공용(키 불필요) | 완전 무료, 한도 없음 |
| 실사진·차트로 표현 불가능한 개념 설명 장면 | 요약 카드(ffmpeg, AI 이미지 생성 없음) | 완전 무료 |
| 내레이션(TTS) | Windows 내장 음성(기본) 또는 로컬 TTS Piper(선택) | 완전 무료, 한도 없음 |
| 렌더링 | ffmpeg | 완전 무료 |
| 로그인 | Google/네이버 OAuth 앱 등록 | 완전 무료 |
| **(선택) 위키미디어에 없는 최신 사진 검색 보강** | Google Custom Search | 선택, 하루 100건 무료 → 이후 유료 |

표의 마지막 줄 하나만 진짜 "쓰면 유료일 수 있는" 선택 기능이고, 나머지는 전부 기본값 그대로
무료입니다. 대신 로컬 LLM(Ollama)은 사용자 PC에 별도 설치가 필요하고(위 2-1번 참고, TTS는
Windows라면 2-2번처럼 설치 없이 됩니다), 무료인 대신 다음 트레이드오프가 있습니다:

- **대본/이미지 판단 품질**: 로컬 LLM은 Gemini보다 한국어 문장력·형식 준수도가 낮을 수
  있습니다. 결과가 부자연스러우면 더 큰 로컬 모델로 바꿔보세요.
- **처리 속도**: PC 사양(특히 GPU 유무)에 따라 대본 하나 쓰는 데 몇 초~몇 분까지 차이가
  큽니다. 무료 API 한도에 막혀 며칠씩 기다리는 것보다는 대체로 훨씬 빠릅니다.
- **실사진 커버리지**: 위키미디어 공용은 백과사전형 저장소라 인물/기업 로고/지도/역사적
  사진에는 강하지만 "이번 주 뉴스 현장 사진"류는 잘 없습니다 — 못 찾으면 안내 카드로
  자동 대체됩니다(화면에 대체 이유가 표시됨).
- **뉴스 링크**: 구글 뉴스 RSS의 링크는 news.google.com을 경유하는 리디렉션 URL입니다
  (원문 URL 직링크가 아님) — 클릭하면 실제 기사로는 이동되지만, 정확한 원문 URL이 필요한
  경우 알아두세요.

## 6. 대본 구조

1. **훅(오프닝)**: 리서치에서 확인된 가장 강력한 사실로 시작해 강하게 예고
2. **현황**: 지금 무슨 일이 벌어지고 있는지
3. **원인**: 왜 이런 일이 발생했는지
4. **과거 사례**: 과거에는 어떤 일이 있었는지
5. **영향**: 관련 기업/국가/시장에 어떤 영향이 있는지
6. **숫자와 자료**: 실제 확인된 수치
7. **전문가 관점**: 시장/전문가 의견
8. **전망**: 앞으로 어떤 일이 벌어질 수 있는지
9. **핵심 정리**: 시청자가 알아야 할 핵심 요약(또는 전망형 마무리)

목표 길이가 짧으면(5~10분) 2번~8번 관점을 적은 챕터에 압축해서 담고, 길면(60~110분)
관점마다 챕터를 여러 개 배정합니다 — 항상 9단계 구조 자체는 유지하되 분량만 조절됩니다.

## 7. 시각자료 소싱 방식

장면마다 "무엇을 보여줘야 하는가"를 먼저 판단합니다(대본을 먼저 쓰고 아무 이미지나 붙이는
방식이 아님):

- **실제 인물/사건/장소 사진, 기업 로고, 지도**가 필요한 장면 → 위키미디어 공용에서 먼저
  검색(항상 시도, 키 불필요). 못 찾고 `GOOGLE_CSE_API_KEY`가 설정되어 있으면 두 번째로
  시도. 그래도 못 찾으면 "실제 이미지를 찾지 못함" 안내 카드로 대체(화면에 명시 — 허구
  이미지를 실제 사진인 척 보여주지 않기 위해 AI 이미지 생성을 쓰지 않습니다).
- **주가/환율/통계 등 실제 수치**가 핵심인 장면 → 외부 차트 서비스 없이, 리서치 단계에서
  확인한 실제 숫자를 ffmpeg로 직접 그린 데이터 카드로 표시(숫자를 지어내지 않음).
- **실사진·차트로 표현할 수 없는 추상적 개념 설명** → 장면 문장을 요약한 개념 카드(ffmpeg로
  직접 그림). 예전에는 AI 이미지 생성을 썼지만, Google API 의존을 없애면서 AI 삽화 자체를
  없앴습니다 — 사진처럼 보이는 허구 이미지보다 "이건 요약 카드다"가 명확한 쪽이 사실 전달에
  더 적합하다는 판단입니다.

## 8. 최종 렌더링

`ffmpeg`로 아래 순서를 자동 처리합니다(`lib/economic/render.ts`).

1. 훅(재활용된 본문 장면 시각자료로 만든 빠른 몽타주)과 모든 본문 장면(시각자료 + 느린
   확대/이동 + 자막 + 출처 표기)을 각각 무음 영상 클립으로 렌더링(동시 실행 수 제한 +
   클립별 타임아웃)
2. 모든 클립을 순서대로 이어붙임(스트림 복사)
3. 훅 내레이션 + 모든 장면 내레이션을 순서대로 이어 붙여 하나의 오디오 트랙으로 조립
4. (배경음을 켰다면) 내레이션 아래 낮은 볼륨으로 믹싱
5. 무음 영상 + 오디오를 합쳐 `public/renders/<프로젝트id>.mp4`로 저장

화면 하단에는 자막(문장 단위, 흰 글자+검은 외곽선)과 별개로, 시각자료의 출처가 있으면
작은 글씨로 함께 표시됩니다(뉴스 방송의 "자료: ○○" 하단 표기 스타일).

## 자막 폰트

한글 자막을 넣으려면 한글 지원 폰트 파일이 필요합니다. `CAPTION_FONT_PATH`로 직접
지정하거나, Windows(맑은 고딕)/macOS/Linux 순으로 흔한 한글 폰트를 자동으로 찾습니다.
찾지 못하면 자막 없이 렌더링하고 완성 화면에 안내 문구를 보여줍니다.

## 프로젝트 구조

```
app/
  page.tsx                     로그인→내 프로젝트→입력→리서치→대본→장면→음성→편집→검수→렌더링→완료
  providers.tsx                NextAuth SessionProvider 래퍼(클라이언트 컴포넌트)
  api/auth/[...nextauth]       로그인 콜백(Google/네이버)
  api/economic/projects        프로젝트 생성/조회/이름변경/삭제(로그인한 사용자 것만)
  api/economic/projects/[id]/... 리서치/대본/장면/시각자료/내레이션/렌더링 각 단계 트리거·수정·재시도
lib/
  auth.ts                       NextAuth 설정(Google 기본 제공 + 네이버 커스텀 프로바이더)
  common/
    localAI.ts                  로컬 LLM(Ollama) 텍스트/JSON 생성 + 음성 합성(Windows 내장 TTS 기본, Piper 선택) 호출 래퍼
    rssNews.ts                   구글 뉴스 RSS 검색(키 불필요, 완전 무료)
    ffmpegBase.ts, fonts.ts, concurrency.ts   도메인 무관 공용 유틸
  economic/
    types.ts                    프로젝트/대본/장면/출처 데이터 모델(+ PDF 실측 상수)
    authGuard.ts                 API 라우트 공용 로그인/소유권 검사 헬퍼
    research.ts                  최신 뉴스 리서치(구글 뉴스 RSS + 로컬 LLM 요약) + 출처 정리
    script.ts                    대본 생성(아웃라인→훅→챕터→정리) + 제목 공식 점수 계산
    scenes.ts                    대본을 장면 단위로 분할 + 장면별 "무엇을 보여줄지" 판단
    imageSearch.ts               실제 이미지 검색(위키미디어 공용 기본 + Google Custom Search 선택)
    dataCard.ts                  실제 수치 기반 데이터 카드 렌더링(ffmpeg)
    visuals.ts                   장면별 시각자료 소싱 오케스트레이션
    tts.ts                       전체 내레이션(단일 화자) 생성
    render.ts                    최종 영상 조립(ffmpeg)
    store.ts                     프로젝트 상태 파일 저장(사용자별 체크포인트/재개/이름변경/삭제)
    audio.ts                     선택적 배경음 파일 선택
    lock.ts                      파이프라인 단계 중복 실행 방지
```

## 알아두면 좋은 점

- 완성된 영상은 세로 쇼츠가 아니라 일반 유튜브 롱폼 형식인 **가로 1920×1080**입니다.
- 대본/장면판단은 로컬 LLM(Ollama), 내레이션은 Windows 내장 음성(또는 Piper)에서 처리되므로
  API 요금 걱정은 없지만, PC 성능에 따라 처리 시간이 달라집니다 — 자세한 내용은 위 "무료로
  되는 부분" 참고.
- 자막은 문장 단위로 표시되며, 정확한 타이밍은 각 내레이션 청크의 실제 음성 길이를 문장
  글자수 비율로 나눠 근사합니다(단어 단위 강제 정렬 도구를 쓰지 않으므로 완벽히 프레임
  단위로 맞지는 않습니다).
- 대본은 리서치 단계에서 확인한 사실에만 근거하도록 프롬프트로 강제하지만, AI 생성 결과이므로
  게시 전 사람이 한 번 더 사실관계를 검수하는 것을 권장합니다.
- Google/네이버 로그인이 필요합니다. 프로젝트는 사용자별로 분리 저장되며, 다른 사용자의
  프로젝트 id를 알아도 API가 소유권을 검사해 열람/수정할 수 없습니다.
